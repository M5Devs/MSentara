## The two real bugs (both silent in Release)

1. **Missing `sg_commit()`.** sokol_gfx defers resource creation and
   buffer/image updates to `sg_commit()`. Without it the UI still drew (pure
   ImGui draw-list geometry) but the offscreen 3D viewport sampled a black
   texture — the Image rendered, just empty. Fix: call `sg_commit()` once at
   the end of `frame_cb()`, after the swapchain pass ends. `sokol_imgui.h`
   never calls it itself (grep: 0 hits).

2. **MSAA sample-count mismatch on the offscreen target.** `sg_image_desc`
   render-target images inherit `sg_desc.environment.defaults.sample_count`
   (= the swapchain MSAA count, 4 here) when left at 0. The pipelines were
   built at 1, so Debug builds panicked with
   `VALIDATE_APIP_ATTACHMENT_SAMPLE_COUNT`. Fix: set `sample_count = 1`
   explicitly on the color + depth images. Pipelines also hardcode
   `desc.sample_count = 1` to match.

Both were invisible in Release because `SOKOL_ASSERT`/validation is compiled
out. **Always reproduce sokol problems in a Debug build** — the validation
layer names the exact log item.

## 2026-11-17 (later) — Milestone 2: VMD motion import + Bezier + timeline playback

- Read the VMD sources (saba `VMDFile.cpp`, `VMDAnimation.cpp`, `MMDFileString.h`)
  **before** coding, per the references rule. Key layout facts confirmed:
  - Header `"Vocaloid Motion Data 0002"` in 30 bytes + 20-byte Shift-JIS name;
    the pre-0002 variant uses a 10-byte name.
  - Bone keyframe = 111 bytes: `name[15]`, `u32 frame`, `vec3 pos`,
    `quat (x,y,z,w)`, 64-byte interp block. Morph keyframe = 23 bytes.
  - **The 64-byte interp block is FOUR identical 16-byte copies**; within a
    copy, byte `(control*4 + channel)` with control 0..3 = x0,y0,x1,y1 and
    channel 0..3 = X,Y,Z,rot. So X-curve = bytes 0,4,8,12; rot = 3,7,11,15.
    Control = byte/127. (I nearly read it as four sequential curves — that
    would silently swap the channels.)
  - MMD is **left-handed**; mirror Z: translation `(x,y,-z)`, quaternion
    `(-x,-y,z,w)` (conjugate by diag(1,1,-1), still a proper rotation). A
    rotation about Z is unchanged — good sanity check.
- New core module `src/core/Animation.{hpp,cpp}`: `Bezier` (cubic with p0=0,
  p3=1; `ease()` bisects x(t)=time in 24 iters @1e-5 tol, then returns y(t)),
  `BoneKey`/`BoneTrack` (per-axis Bezier + rot curve), `ScalarTrack` (morphs),
  `AnimationClip`, `apply_clip()` mapping tracks to bones **by name** and
  writing the sampled quat into `pose.delta` as Euler degrees.
- Added `quat_to_euler_degrees` / `euler_degrees_to_quat` to `Transform`, via
  `Transform::from_matrix(glm::mat4_cast(...))` so the Euler convention has a
  single definition. Round trip verified exact (worst 1.3e-14).
- New formats: `VmdLoader.{hpp,cpp}` (bounds-checked reader, count sanity
  guards, morph→scalar tracks, camera/light/IK deliberately unread),
  `ShiftJis.{hpp,cpp}` + generated `SjisTable.hpp` (CP932→UTF-8, no
  ICU/iconv; `scripts/gen_sjis_table.py`).
- UI/platform: `--vmd <path>` / `MSENTARA_VMD=`, File>Import VMD, functional
  timeline transport (play/pause/step/scrub/reset), keyframe ticks on the

- `scripts/make_test_vmd.py` writes a synthetic motion keyed to the synthetic

## Detailed milestone notes (moved out of MEMORY.md to keep the index small)

### Milestone 1 — PMX parsing + skeletal skinning
- `src/formats/PmxLoader.cpp`: bounds-checked PMX 2.0/2.1 reader
  (`Reader` with `u8/i8/u16/i16/u32/i32/f32/vec*/text/index/skip/count`).
  Text is length-prefixed UTF-16LE or UTF-8 per the global flag.
- **PMX vertex weight types** (felixjones spec + benikabocha/saba `PMXFile.cpp`;
  see `docs/REFERENCES.md`): `0=BDEF1` (one index, implicit weight 1.0),
  `1=BDEF2` (two indices + **4-byte IEEE-754 float** weight; second bone gets
  `1 - w`), `2=BDEF4` (four indices + four float weights), `3=SDEF` (BDEF2 form
  plus three `vec3` C/R0/R1 = 36 bytes), `4=QDEF` (BDEF4 form). The `[0,100]`
  **byte** weight is the older **PMD** format, NOT PMX — using it desynchronises
  the whole vertex section. Each vertex then carries its **own edge-scale float**
  immediately after its weights (per-vertex, not a trailing array).
- **Handedness**: MMD is left-handed Y-up Z-forward; mirroring Z
  (`vec3(x, y, -z)`) converts to GL/GLM right-handed AND flips triangle winding,
  which is exactly what CCW pipelines want, so indices are used unchanged.
- **`src/core/Skeleton.cpp` `resolve_order`**: cycle-safe iterative DFS. A bone
  whose parent is already on the DFS stack must be emitted to break the cycle,
  else the loop never terminates (a real hang; `test_deep_hierarchy_and_cycles`
  2000-bone case exposed it).
- **CPU skinning** (`skin_mesh`) streams into a transient vertex buffer each
  frame, so no bone-matrix uniform array is needed. `src/ui/ModelInstance.cpp`
  owns model + pose + GPU resources and is the only place tying core to renderer.

#### sokol revision pinned here (f5e8833) — API differences from older docs
- Textures use **separate** `sg_image` + `sg_view` + `sg_sampler`, bound via
  `sg_bindings.views[i]` / `sg_bindings.samplers[i]`.
- Shader texture binding: `sg_shader_desc.views[i].texture.{stage,image_type,
  sample_type}` (note the nested `.texture`), `…samplers[i].{stage,
  sampler_type}`, and a `texture_sampler_pairs[i]` naming the GLSL sampler
  uniform (`glsl_name`) — required on GL 4.1 / WebGL2.
- Per-frame vertex data: `.usage.write_transient = true` + fixed `.size`, then
  `sg_write_buffer_transient()` **outside** a pass, drawn the same frame.
  Growing it means destroy + recreate.
- `sg_write_buffer_unsealed` + `sg_seal_buffer` is the separate path for
  immutable one-shot uploads.
- `ImageIO.cpp` holds the single `STB_IMAGE_IMPLEMENTATION` (private include
  dir), normalises every source to RGBA8 with
  `stbi_set_flip_vertically_on_load(1)`, and a 1x1 white texture is the
  untextured-material fallback so the shader has no branch.

### Milestone 2 — VMD motion (src/core/Animation, src/formats/VmdLoader)
- **VMD layout** (saba-verified; also in `docs/REFERENCES.md`): header
  `"Vocaloid Motion Data 0002"` (30 B) + 20 B Shift-JIS name (pre-0002 variant:
  10 B name); bone key = 111 B (`name[15]`, `u32 frame`, `vec3 pos`,
  `quat x,y,z,w`, 64 B interp); morph key = 23 B.
- **The 64-byte interp block is FOUR identical 16-byte copies.** Byte
  `(control*4 + channel)`, control 0..3 = x0,y0,x1,y1, channel 0..3 =
  X,Y,Z,rot. X-curve = bytes 0,4,8,12; rot = 3,7,11,15; control = byte/127.
  Do NOT read it as four sequential curves — that silently swaps channels.
- **Left-handed → right-handed**: translation `(x,y,-z)`, quaternion
  `(-x,-y,z,w)` (conjugate by diag(1,1,-1)). Rotation about Z is unchanged.
- `Bezier::ease()` bisects `x(t)=time` (24 iters, 1e-5 tol) then returns
  `y(t)`. `apply_clip()` matches tracks to bones **by name** and writes the
  sampled quat into `pose.delta` as Euler degrees (via
  `quat_to_euler_degrees`, which reuses `Transform::from_matrix`).
- `ShiftJis.{hpp,cpp}` + generated `SjisTable.hpp` (CP932→UTF-8, no
  ICU/iconv; regen with `scripts/gen_sjis_table.py`). `kDoubleByte` is
  `(key<<16|cp)` sorted for binary search; `kSingleByte[256]` holds ASCII +
  half-width katakana.
- `scripts/make_test_vmd.py` keys a motion to the synthetic PMX's `root`/
  `child` bones. Env vars: `MSENTARA_PMX`, `MSENTARA_VMD`, `MSENTARA_FRAME_LIMIT`.

### Milestone 3 — morphs, append transforms, IK (src/core/Morph, Skeleton, PmxLoader)
- **`Morph.hpp/.cpp`**: `MorphTarget{kind, vertex_offsets, uv_offsets,
  bone_offsets, material_offsets, group_refs}`; `MorphSet` with
  `add/find/target/size/weights/reset_weights/set_weight`. Group morphs are
  flattened to leaf weights at evaluation with a visited set (cycle-safe).
- **Append/grant** ("inherit"): a bone copies a weighted slerp of its
  append-parent's *animated* rotation and/or translation. MMD composes
  `local = T * (ik * animate * append) * S`.
- **CCD-IK**: per link (tip-first) rotate so effector→link lines up with
  target→link; axis `cross(ikDir, targetDir)`; clamp `limitRadian`. The IK
  rotation lives on the effector *and* every link. Angle-limited links clamp
  axis-by-axis in Euler XYZ; Z-mirror negates both bounds.

### Milestone 4A — fresh FetchContent, `.msentara` project format, CI
- **Fresh-fetch bug root cause**: `GIT_SHALLOW TRUE` on a *commit*-pinned
  FetchContent does `git clone --no-checkout --depth 1 --no-single-branch`
  then `git checkout <sha>`. A SHA that is not a branch tip (sokol's is not)
  is absent from the depth-1 history → `fatal: unable to read tree`. Fix: drop
  `GIT_SHALLOW` from the commit-pinned clones (sokol/imgui/imguizmo) and pin stb
  to a SHA too. glm (tag 1.0.1) and nlohmann/json (release URL+hash) keep
  shallow/URL fetching — a tag IS a tip so shallow is safe. Documented in
  `cmake/MSentaraDependencies.cmake`; do not "optimise" it back.
- **nlohmann/json** is fetched as the small `include.zip` release asset
  (v3.11.3, SHA256 a22461d1…) rather than a git clone; exposed as an INTERFACE
  target, linked **PRIVATE** into `msentara_core`.
- **`.msentara` format** (`src/core/ProjectIO.{hpp,cpp}`): versioned JSON,
  `format:"msentara-project"`, `version:1`. Stores model/motion *paths* plus
  timeline/camera/ik/physics + name-keyed morph weights and bone deltas (only
  non-default ones). `project_to_json` is deterministic (fixed key order,
  `dump(2)`) so save→load→save is byte-identical. Wrong `format`/`version` is
  rejected; a wrong-typed field falls back to its default (never throws).
  CLI: `--project <p>` (supersedes `--pmx`/`--vmd`) + `MSENTARA_PROJECT`.
- **Timeline** gained a `loop` flag; `advance()` clamps+stops when loop=false.
- **Shaders are backend-portable**: `Renderer.cpp` builds each GLSL program as
  `kGlslPrologue + <shared body>`; prologue is `#version 410` on desktop and
  `#version 300 es` + `precision highp {float,int,sampler2D};` under
  `__EMSCRIPTEN__`. The ES `sampler2D` precision is required. Web link flags
  need `-sMIN/MAX_WEBGL_VERSION=2`.
- **CI** `.github/workflows/ci.yml`: linux (gcc+clang, Debug, ctest + Xvfb
  headless smoke), windows (MSVC/Ninja), emscripten (emsdk 3.1.61 → uploads
  `MSentara.{html,js,wasm}`). Every job configures from scratch, so a broken pin
  fails CI. CI verified green on push (commit aaf746b). Repo remote is
  `M5Devs/MSentara` (owner M5Devs, not the workspace dir name).

## Milestone 5 — VMD camera track + offline PNG sequence export (2026-11-18)

- **VMD camera keys** (`src/formats/VmdLoader.cpp`): a camera key is 61 bytes
  (frame u32, distance f32, interest vec3, rotate vec3, 24-byte interp,
  view_angle u32, perspective u8). The 24-byte interp block is **six sequential
  4-byte curves** (X, Y, Z, rot, distance, FOV), each `(x0,x1,y0,y1)` — a
  *different* layout from the bone block's interleaved `(control*4+channel)`
  bytes. Do not reuse the bone reader. The section is optional (a file may end
  after the morphs). `interest` mirrors Z like every other position; the Euler
  `rotate` is stored **unmirrored** (Camera composes it).
- **Camera rig** (`src/core/Camera.*`): VMD's orientation is `Ry*Rz*Rx`; with
  zero roll that equals the orbit convention with `yaw=y`, `pitch=-x`. Added a
  `roll` field; `right()/up()` rotate the orbit basis about forward by roll.
  `apply_vmd_state`/`vmd_state` are inverses. `pitch` is clamped to +-89.
- **CameraTrack** (`src/core/Animation.*`): `CameraKey` holds a `CameraState`
  + six `Bezier` curves. `sample()` reproduces saba's
  `VMDCameraController::Evaluate`, **including the hard-cut rule: two keys one
  frame apart hold the earlier key instead of interpolating**. Outside the keyed
  range the nearest key is held. `AnimationClip::frame_end()` now includes the
  camera track; `empty()` too. `apply_camera_clip(clip, frame, camera)` returns
  false (camera untouched) when there is no camera track.
- **Offline export** (`src/main.cpp` + `src/platform/ImageIO.cpp`): one frame is
  rendered **per `frame_cb`**, not in a loop. sokol allows only one transient
  vertex-buffer write per frame (skinning), so a multi-frame export must span
  frames. Each step: apply animation → `model.update(renderer, 0.0f)` (dt 0 pins
  physics for reproducibility) → apply camera clip → begin offscreen pass →
  draw → `read_color_pixels` **while the pass is still bound** (sokol unbinds on
  end_pass) → end_pass → single `sg_commit()` → write PNG. No `sg_commit()`
  between the transient write and the draw, else
  `VALIDATE_DRAW_WRITE_BUFFER_TRANSIENT_MISSING`.
- **Uniform output size**: the export pins width/height to the **viewport panel
  rect**, but that rect is only known after the first UI layout. Gate the export
  start on `panel_known` (panel w/h >= 1) AND `g_target_w > 0`, and never resize
  the offscreen target while `g_export.active`. Without the gate, frame 0 was
  full-window (1600x900) and later frames the panel size (1150x679).
  `ExportRequest.width/height > 0` overrides the panel size.
- **`write_png_rgba`** uses stb_image_write in the same TU as stb_image (no
  shared state). `read_color_pixels` uses `glReadPixels` — needs a guarded GL
  include in `Renderer.cpp` (sokol only pulls GL headers under `SOKOL_IMPL`).
- **CLI**: `--export <dir> [--export-start N] [--export-end N] [--export-camera]`
  renders once then quits. UI: File > Export PNG Sequence… modal + a "VMD
  Camera" checkbox in the Timeline panel (only shown when the clip has a camera).
  Project format gained `camera.roll/fov_y/orthographic` + `use_vmd_camera`
  (all default so older files load unchanged).
- **Verified**: Debug `-j 1` 0 warnings, `ctest` 11/11. ASan+UBSan tests 11/11
  clean; ASan app headless export clean (only Mesa `libGLX_mesa.so.0` leaks, no
  MSentara frames). Headless export: bone+morph motion → 5 frames all 1150x679
  and pixel-different; camera motion with `--export-camera` → 31 frames, frame 0
